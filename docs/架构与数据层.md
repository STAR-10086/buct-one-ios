# 架构与数据层设计

## 一、五层 SwiftPM 编译期隔离

`Packages/BuctCore` 通过 `Package.swift` 目标依赖关系在编译期强制约束模块边界，并由 `.github/workflows/check.yml` 在每次提交时执行静态扫描：

```text
App / WidgetExtension
  └── 仅允许 import: BuctModel, BuctStore, BuctSync（严禁直接 import BuctNetwork / BuctSources）
        └── BuctSync
              ├── BuctSources（按业务域拆分子目录，子域间严禁互相引用）
              │     ├── Academic/   (jwglxt / gmis)
              │     ├── Portal/     (i.buct.edu.cn / mnews.buct.edu.cn)
              │     ├── JwNotice/   (jwglxt 个人消息与公告)
              │     └── Theol/      (course.buct.edu.cn 北化在线)
              ├── BuctNetwork       (TLS / CookieJar / Crypto / WebVPN / sidportal SSO / Passkey)
              └── BuctStore         (Atomic JSON / AppContainerResolver / KeychainVault)
                    └── BuctModel   (零第三方依赖，仅 import Foundation)
```

## 二、数据层四条铁律

所有领域持久化切片均封装在 `DomainSlice<T>`（位于 `BuctModel/DomainSlice.swift`）并由 `DomainSliceStore<T>`（位于 `BuctStore`）统一落盘：

1. **失败永不产生新 `data`**：网络或解析失败时，只更新 `provenance.refreshState`（有旧数据转为 `.failedFallback`，无旧数据保持 `.never`）与 `provenance.lastError`，旧 `data` 原样保留。
2. **`never` ≠ `emptyConfirmed`**：从未同步过（`.never`）时 UI 应引导刷新/登录，严禁显示「暂无数据」误导用户；仅当服务端明确返回空列表时才写入 `.emptyConfirmed`。
3. **`parserVersion` 只增不减**：任何解析规则变更必须同步递增对应 `Parser.parserVersion` 与 `DomainSliceStore.parserVersion`。读取旧版本缓存时自动降级为 `.stale` 提示静默刷新。
4. **`capturedAt` 单调不减**：写入时间戳固定取 `max(previous.provenance.capturedAt, now)`，防止系统时间回拨导致缓存新鲜度异常。

## 三、网络、认证与安全机制

- **校方双链 TLS 校验（`BuctTlsDelegate`）**：
  - 所有网络请求经由 `BuctHttpTransport.shared`（禁止自动重定向、禁用系统全局 `HTTPCookieStorage`）。
  - 优先走系统根证书信任，若失败则用内置 4 张校方 CA 证书（GlobalSign / Sectigo 等）执行链式锚点校验，禁止任何地方绕过证书验证。
- **校外 WebVPN 自动降级（`BuctWebVpnManager`）**：
  - 仅对 7 个校园内网限定域名（`scs`、`eapi`、`ecard`、`gmis`、`i.buct`、`mnews`、`tree.buct.edu.cn`）执行 **3 秒直连优先探测**。
  - 直连超时或遭遇校内网关拦截时，自动通过 `w.buct.edu.cn`（Wengine AES-128-CFB URL 编解码）代理并自动换取/刷新票据，记忆有效期 5 分钟；校外可直连域名（如 `jwglxt`、`course`）绝不走 WebVPN。
- **单飞静默续期（`SsoSilentRelogin`）**：
  - 跨所有业务域共享同一把 `SsoSilentRelogin` 互斥锁，出现会话过期时先尝试使用 Keychain 加密保存的凭据静默重登；失败后进入 30 秒冷却窗口避免高频重试风控，用户主动点击刷新时可穿透冷却。
- **软件通行密钥（`BuctSoftwarePasskey`）**：
  - 原生实现 EC P-256 密钥对 + RFC 8949 CBOR 编码器对接 `sidportal` WebAuthn 接口，免除浏览器弹窗登录。
- **Keychain 与隐私红线**：
  - `KeychainVault` 严禁指定 `kSecAttrAccessGroup`（确保免费个人证书与 LiveContainer 不报 `-34018`），统一使用 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` 防止 iCloud 同步泄露。
  - 日志全部经过 `LogRedactor` 脱敏，不输出学号、姓名、密码与 Cookie。
  - 仅保留可由用户在「我的 → 数据与安全」随时关闭的自托管 Umami（`https://stats.buct.one`）零 PII 匿名统计。

## 四、iOS 26 原生 Liquid Glass 规范

- **独立玻璃卡片**：工作台 4 列栅格（`totalCols = 4`、`MINI = 1×1`、`MEDIUM = 2×2`、`LARGE = 4×2`）与长列表中的玻璃卡片禁止用外层 `GlassEffectContainer` 包裹，避免 iOS 26 液态玻璃邻近融合导致卡片边界粘连。
- **大列表懒加载**：所有课表、成绩、培养方案树、资讯与作业列表均使用 `LazyVStack`，避免上百张玻璃卡片同时离屏渲染导致掉帧。
- **WidgetKit 并发安全**：在 Swift 6 `complete` 严格并发模式下，`TimelineProvider` 采用同步读取 `AppContainerResolver.resolveRootDirectory().url` 下的 `today_widget_snapshot.json`，避免向非 `@Sendable` completion 闭包跨任务传递状态。
