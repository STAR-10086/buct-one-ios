# 自签与安装指南（iOS 26.0+）

BUCT One iOS 版采用**全云端无签名构建**，每次推送至 `main` 均会在 GitHub Actions `macos-26` 上自动打包单一无扩展 `.ipa` 并滚动发布至 `dev-latest` Pre-release。

---

## 一、安装包说明

| 版本 | 文件名 | Bundle ID | 体积 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **标准无扩展版** | `buct-one-ios-v*-unsigned.ipa` | `com.buct.one` | ~6.5 MB | **SideStore / AltStore / LiveContainer / Sideloadly / Feather / ESign 全兼容**；不含 `.appex` 插件与 App Group 权限，仅占 **1 个 App ID** |

> [!TIP]
> 免费个人 Apple ID 每 7 天最多注册 **3 个 App ID**（且同时最多激活 3 个应用）。不含扩展的单包设计可最大限度节省 App ID 名额并避免自签小组件权限问题。

---

## 二、各工具安装方式

### 1. SideStore / AltStore（推荐软件源安装）

1. 在 SideStore（或 AltStore）中打开 **Sources（软件源）→ 右上角 `+`**，添加软件源：
   - **开发预览源（跟随 `main` 实时更新）**：
     ```text
     https://github.com/STAR-10086/buct-one-ios/releases/download/dev-latest/apps.json
     ```
   - **正式版源（R2 托管源清单，包体由 GitHub Releases 下载）**：
     ```text
     https://update.buct.one/ios/apps.json
     ```
2. 在源列表中选择「**北化一站**」直接安装；后续可在 SideStore 中无电脑一键更新与续签。

#### 常见问题排查（SideStore）

- **问题 A：直接粘贴 GitHub `.ipa` 链接到「Install from URL」时报错 `The bundle ID "com.buct.one" does not match the one specified by the source`**
  - **原因**：SideStore Nightly 在处理非 `file://` URL 时会把 `.ipa` 文件名（例如 `buct-one-ios-v0.1.0-unsigned`）当作预期的 Bundle ID，与包内真实的 `com.buct.one` 比对失败。
  - **解决方法（任选其一）**：
    1. **优先使用上方的 `apps.json` 软件源安装**（源清单已准确声明 `com.buct.one`）；
    2. 或先用 Safari 将 `.ipa` 下载到系统「文件」App，再点 SideStore 右上角 `+` → **Choose from Files** 从本地导入；
    3. 或在 SideStore `Settings → App Verification` 中临时关闭 `Bundle ID Verification`（也可将本地文件重命名为 `com.buct.one.ipa` 后导入）。

- **问题 B：SideStore 内直接下载报 `Archive appears to be corrupt: CFNetworkDownload_xxx.tmp`**
  - **原因**：部分国内网络直连 GitHub CDN 时 SideStore 后台下载流会被中途截断（SideStore 上游已知问题 `#1757`），导致写入临时目录的 `.tmp` 不完整。
  - **解决方法**：先使用代理在手机 Safari 或电脑浏览器把完整 `.ipa` 下载到本地「文件」App，再通过 SideStore 的 **Choose from Files** 导入安装。

---

### 2. LiveContainer（免占用 3 应用槽位）

1. 从 [dev-latest Release](https://github.com/STAR-10086/buct-one-ios/releases/tag/dev-latest) 下载**标准无扩展版**（`buct-one-ios-v*-unsigned.ipa`）。
2. 在 LiveContainer 中导入并运行。
3. App 内的 `AppContainerResolver` 与 `KeychainVault` 已针对 LiveContainer 做过兼容处理（不写入 `kSecAttrAccessGroup`、无 App Group 时自动退回主沙盒），可正常登录与持久化缓存。

---

### 3. Sideloadly / Feather / ESign

- 本仓库产出的 `.ipa` 在 CI 中均已执行：
  1. `plutil -convert xml1` 规范化 `Info.plist`；
  2. 由内而外（先 `.appex` 再 `.app`）`codesign --force --sign -` 注入 ad-hoc `LC_CODE_SIGNATURE` 与对应 `.entitlements`；
  3. 零 extra-field 纯 ZIP32 `ZIP_STORED` 打包并通过 `SideSign` 解析器同款校验。
- 直接拖入 Sideloadly 或导入 Feather / ESign 重签即可安装。
